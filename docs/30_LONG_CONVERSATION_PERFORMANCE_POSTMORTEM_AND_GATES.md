# 长篇对话卡顿：原因调研、修复和回归门禁

日期：2026-10-12。范围：Knowledge Master 的 AI 智囊消息流及独立单文件入口。

## 结论与证据边界

已在本地源码和真实浏览器中复现前端性能瓶颈：每一个正文、推理或工具参数分片，都会同步保存全部会话，并重建当前会话的全部消息。历史越长，重复工作越多；写入 DOM 后又读取滚动高度，进一步增加布局开销。

截图中的“加载中”“Agent 循环第 1/5 步”只能说明生成尚未完成，不能单独证明主线程卡顿，也不能据此判断模型服务异常。本次没有用户原始请求的网络时间线和 Performance trace，因此确认的是本地可复现的前端瓶颈，不把它冒充为截图现场的唯一原因。

已实施局部更新、分片刷新合并、定期保存和终态立即保存，并重新生成 `index.html`。

## 原始调用链

```text
client.js: fetchEventSource.onmessage
  ├─ accumulatedContent / accumulatedReasoning / partialArgs
  └─ agent-loop.js: onContent / onReasoning / onToolCallFragment
       ├─ SessionStore.updateMessage
       │    └─ saveSessions → JSON.stringify(全部 sessions) → localStorage.setItem
       └─ AiAgentUIController.renderCurrentSession
            ├─ container.innerHTML = ''
            ├─ 遍历全部 messages
            │    └─ renderMarkdown / renderReasoningCard / renderToolCard
            └─ container.scrollTop = container.scrollHeight
```

| 原因 | 本地证据 | 影响 |
| --- | --- | --- |
| 全历史重复渲染 | 三类分片回调均立即调用全量渲染 | 每次重复解析历史 Markdown、创建 HTML 和 DOM |
| 全会话同步保存 | `updateMessage` 原实现无条件 `saveSessions` | 序列化和同步存储竞争主线程时间 |
| 强制滚动和布局计算 | 全量 DOM 写入后读取 `scrollHeight` | 阅读历史被拉回底部，大树布局成本放大 |
| 交互状态被销毁 | 旧消息节点被清空重建 | 推理折叠状态和文本选择易丢失 |
| 单条超长输出的累计解析 | Markdown 与工具参数使用累计文本 | 即使移除历史放大因素，当前巨型消息仍有解析成本 |

设历史文本总量为 H、当前累计输出长度为 L、分片数为 K，旧渲染的重复处理规模近似为 `K × H + ΣL`，存储还重复处理全部会话。修复后，流式渲染不再渲染或解析历史内容，只在合并刷新时处理当前消息；定位目标消息仍会扫描消息 ID。这里描述的是工作量关系，不是实测 CPU 复杂度或内存上界。

Web Storage 的同步性质见 [MDN Web Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)。DOM 写入后读取几何信息可能触发同步布局，见 [web.dev：避免复杂布局与布局抖动](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing)。这两项资料解释机制；根因定位依据仍是本项目调用链和浏览器复现。

## 浏览器复现与测量

使用本地静态服务、Chromium 浏览器、合成数据，不调用外部模型，不发送真实对话或密钥。

原始页面骨架中的固定样本：100 条 assistant 历史消息，每条由 `段落 **重点** 内容\n\n` 重复 100 次组成；循环更新最后一条消息 100 次，每次内容为 `输出段落\n\n` 重复 100 次再加循环编号。初始挂载不计时；测量更新循环。

保存介质替换为计数函数，仍执行真实 `JSON.stringify(sessions)`，因此下面的“保存次数”是保存路径调用次数，**不是磁盘写入实测**。旧路径立即渲染全历史，新路径使用 `persist: false` 并立即局部渲染，以隔离局部渲染改动；实际分片合并另有行为测试。

| 指标 | 修复前 | 修复后同骨架样本 |
| --- | ---: | ---: |
| 100 次刷新耗时 | 44,191 ms | 269 ms |
| 刷新循环内立即保存次数 | 100 | 0 |
| 刷新循环内全会话序列化字符数 | 16,374,590 | 0 |
| 历史消息外层节点保留 | 否 | 是 |

这是同一调研会话的单次合成结果，不能当作所有设备的固定倍数、真实网络响应耗时或生产 SLA。初始化大量历史 DOM 的时间也未被这个数字覆盖。

独立浏览器门禁还使用带推理卡片的样本，最新桌面运行耗时 622 ms，390 × 844 窄屏运行耗时 519 ms，均通过全部行为断言；此前桌面运行耗时为 457 ms。2000 次正文/推理回调合并为一次局部刷新。

## 已执行的修复

| 文件 | 实施内容 |
| --- | --- |
| `features/ai-agent/agent-loop.js` | 三类流式回调只更新内存并请求合并刷新；结束/失败保存终态，中止保存剩余内容并刷新；忽略中止后的迟到回调 |
| `features/ai-agent/session-store.js` | `updateMessage` 保持默认立即保存兼容行为；`persist: false` 合并为一个 1000 ms 保存任务；立即保存会取消延迟任务 |
| `features/ai-agent/agent-ui.js` | 消息 ID 对应稳定外层 DOM；100 ms 合并刷新当前消息；边界渲染跳过内容未变的历史消息，删除失效节点；切换会话取消旧刷新并重建对应视图 |
| 同上 | 更新前判断是否位于底部 80 px 范围内，只对底部读者自动跟随；保留同状态推理/工具卡片的展开状态；`pagehide` 与进入后台时保存待处理内容 |
| `index.html` | 使用已有打包器重新生成，确保双击运行的实际入口包含修复 |

100 ms 是主动合并窗口，不是逐 token 展示承诺；终态渲染立即执行并取消排队刷新。1000 ms 保存使用节流：持续输出也定期保存，不会因不断收到分片无限延期。浏览器后台调度可能延长实际间隔。

正常页面离开会尝试保存，进程崩溃或系统强制终止仍可能丢失上一个保存点之后的分片；保存配额不足仍沿用既有告警行为，本次没有扩大为存储迁移。

## 回归门禁与运行方法

### FE-CHAT-PERF-001：流式调度和保存行为，自动阻断

文件：`tests/unit/agent-stream-performance.test.mjs`。已接入 `gates/run-gates.mjs` 的独立具名门禁，失败会使门禁程序返回非零。

- 1000 次延迟保存更新：立即写入数为 0，定时保存任务只有 1 个。
- 保存点触发后保存一次；最终立即保存取消延迟任务。
- 1000 次刷新请求：只有一个 100 ms 刷新任务，只刷新指定消息。
- 真实 AgentLoop 的 1000 次正文与 1000 次推理回调：立即保存和全量刷新均为 0。
- 完成、断网异常和中止：最后内容保存，延迟任务清空。
- 中止后迟到分片不修改已保存内容、不重新排队。

先写测试并运行：旧代码实际报 `1000 !== 0`。补充中止场景后也先看到迟到分片覆盖正文的失败，再加回调有效性判断。修复后测试通过。

```powershell
node tests/unit/agent-stream-performance.test.mjs
node gates/run-gates.mjs
```

### FE-CHAT-PERF-002：真实 DOM 行为和耗时，浏览器阻断

文件：`tests/browser/agent-stream-performance.html` 和对应 `.mjs`。打开独立测试页即自动运行，断言失败显示 FAIL，并使 `window.gatePromise` 拒绝；无需 API Key。

```powershell
npm run dev
```

在服务输出的端口打开 `/tests/browser/agent-stream-performance.html`。自动化浏览器可等待并读取 `await window.gatePromise`，必须得到 `status: PASS`。本次服务端口为 3017，仅用于验证，不是固定配置。

硬性断言：

- 100 次局部刷新耗时不超过 5000 ms；记录实际耗时，超限阻断。
- 历史外层及内部节点保持同一对象；当前消息外层也保持稳定。
- 阅读历史时不强制滚动；底部读者仍跟随新增内容。
- 当前推理展开状态保持；最终正文完整呈现。
- 2000 次真实流式回调合并成一次刷新，期间无立即保存。
- 页面离开事件清空待保存任务；删除后节点数量匹配。
- 会话视图切换后旧刷新不污染新视图。

该浏览器门禁当前是独立入口，**不由 Node 门禁自动启动浏览器**。发布前需要单独执行并记录 PASS；后续若接入 CI 浏览器，应保持这些行为断言。5000 ms 是固定合成样本的粗粒度防退化阈值，不代表每帧流畅或最大输入延迟已达标。

## 尚需区分的等待与后续优化条件

| 观察现象 | 优先收集的证据 | 处理方向 |
| --- | --- | --- |
| 页面能输入和滚动，但一直加载 | 请求是否发出、首字节/首 token 时间、上游状态 | 模型/网络等待，本次未测真实服务 |
| 工具调用参数特别巨大仍卡顿 | `parsePartialJson`、工具预览的 CPU trace | 分批解析或限频预览；本次未改客户端协议解析 |
| 打开超大历史时卡顿 | 首次挂载耗时、DOM 数量和长任务 | 历史分页或可视区渲染，需要另行设计滚动/搜索兼容 |
| 单条消息特别长仍有长任务 | 当前消息 Markdown 解析耗时 | 完成块缓存、块级增量解析或 Worker |
| 保存点仍有明显停顿 | 实际存储/序列化耗时与数据规模 | IndexedDB 或按会话存储，涉及迁移，不在本次范围 |

没有采取截断模型上下文、删除历史或减少最大输出长度来掩盖前端重复工作，也没有将完整性能诊断扩展为所有协议和存储系统的重写。截图中 100k/63k 是模型规格标签，不能直接当作当前对话的实际 token 数。
