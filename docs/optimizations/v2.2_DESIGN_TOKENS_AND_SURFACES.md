## 一、 优化背景与历史痛点 (视觉与设计混乱)

在 v2.1 架构拆分完成后，系统的视觉体验仍处于“开发态原型”阶段，存在典型的前端设计缺陷：
1. **“结构不够，框来凑”**：所有容器一律套用厚重的高对比度边框（`border border-slate-700`），界面充斥着网格线条噪点，视觉层次严重扁平化。
2. **色彩散落与硬编码**：CSS 与 HTML 中大量硬编码颜色（如 `#1e293b`, `#3b82f6`, `#10b981`），没有统一语义引用，无法实现系统级主题适配。
3. **视觉焦点杂乱（违背 Rule of One）**：一个屏幕内同时出现 4~5 个高饱和度彩色实色按钮，用户无法在 0.5 秒内捕捉到“当前最重要的一步是什么”。
4. **字阶与排版无韵律**：字号、行高随意指定，缺乏基准行高与层次递进。

## 二、 核心设计体系重构 (4层设计令牌与表面阶梯)

```text
┌────────────────────────────────────────────────────────────────────────┐
│                       4-Tier Design Token Architecture                 │
├────────────────────────────────┬───────────────────────────────────────┤
│ Tier 1: Primitive Tokens       │ Tier 2: Semantic Tokens               │
│ • --palette-neutral-950..50    │ • --color-surface-0..4                │
│ • --palette-primary-600..400   │ • --color-text-primary / muted        │
├────────────────────────────────┼───────────────────────────────────────┤
│ Tier 3: Component Tokens       │ Tier 4: Theme Overrides               │
│ • --card-bg, --btn-hero-bg     │ • 暗色工业模式 (Dark Industrial)      │
│ • --stat-card-padding          │ • (可扩展的高对比/明亮模式)            │
└────────────────────────────────┴───────────────────────────────────────┘
```

### 1. 4层设计令牌分层治理
在 `design-system/tokens/` 中系统建立四维设计令牌资产库：
- [`colors.css`](../../design-system/tokens/colors.css)：定义中性基础阶梯、品牌主色、状态语义色及 Surface 语义色。
- [`elevation.css`](../../design-system/tokens/elevation.css)：定义 Surface 0～4 专属明度映射与阴影体系（Surface 阶梯自发提供立体感，而非依赖边框）。
- [`typography.css`](../../design-system/tokens/typography.css)：确立 7 级标准字阶 (`--font-size-xs` 到 `--font-size-3xl`) 及 1.25 / 1.5 行高比例。
- [`spacing.css`](../../design-system/tokens/spacing.css)：确立 8-Point 间距韵律（4px, 8px, 16px, 24px, 32px, 48px）。

### 2. Surface 0～4 表面层级与明度演进
彻底打破“用框线切分容器”的落后手法，依据人类视觉对亮度的感知规律，确立暗色体系下的**明度递进法则**：
- **Surface 0 (底背/环境)**：`#090d16` —— 最深邃的应用底色。
- **Surface 1 (画板/大区)**：`#0d1322` —— 仪表盘大区、侧栏、精读列表背景。
- **Surface 2 (卡片基底)**：`#131c31` —— 模式卡片、知识单元卡片默认静止态。
- **Surface 3 (悬停/活动浮层)**：`#1a2642` —— 卡片悬停提升、激活状态、下拉菜单面板。
- **Surface 4 (模态对话框)**：`#202e50` —— 弹出式 Dialog、CRUD 工坊弹窗。

> **效果**：去除了 80% 的生硬边框，通过微弱的明度差与微妙的环境光晕（Ambient Glow）自然拉开层次，界面通透高级。

### 3. 色彩中性率与 Rule of One 聚焦原则
- **70%~90% 中性色骨架**：全界面大面积采用中性暗灰与高质感中性白文本，饱和彩色严格收敛至 $< 15\%$ 的操作点睛区。
- **Rule of One**：主屏幕仅保留唯一一个带有品牌辉光（Glow）与高对比填充的主行动按钮（推荐 Banner 的“立即开始”），次要按钮全部收敛为幽灵按钮（Ghost）或中性边框按钮。

### 4. 自动化设计门禁 (`FE-DESIGN-001`)
在 `gates/run-gates.mjs` 中接入设计令牌与排版一致性门禁，自动静态扫描源码中是否存在未经令牌映射的散落 Hex 颜色，保证设计规范长期不腐化。
