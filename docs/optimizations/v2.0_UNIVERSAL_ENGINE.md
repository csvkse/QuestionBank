## 一、 优化背景与历史痛点 (v1.0 痛点分析)

在 v1.0（英语动词形态记忆游戏 VerbMaster）时期，系统具有如下严重局限：
1. **领域硬编码锁定**：数据模型死板绑定英语动词（`base, past, pastParticiple, ing, sForm`），其他知识领域（如 HTTP 状态码、医学药理、法律法条、计算机系统原理）完全无法接入。
2. **干扰项生成逻辑单一**：仅针对英语词尾规则做硬编码字符串变形，缺乏跨领域的自适应混淆能力。
3. **知识编辑门槛高**：使用者必须手写特定的 JSON 数组，无法直接将日常学习积累的 Markdown 笔记转化为可测验题目。
4. **单文件膨胀**：代码全部堆叠在单个文件中，难以扩展复杂学习模块。

### 1. 通用知识图谱数据协议 (`KnowledgeDeck v2.0`)
将业务实体完全抽象为三维正交坐标系：
- **Group (业务大类/业务分组)**：知识体系的一级宏观分类（如 `信息响应 (1xx)`、`重读闭音节动词`）。
- **Category (细分类别/考点特征)**：同组内的特征归属（如 `成功响应`、`双写尾字母加-ed`）。
- **Layer (认知层级/布鲁姆深度)**：`L1-识记`、`L2-理解`、`L3-辨析`。

题目条目 `Item` 统一结构：
```typescript
interface KnowledgeItem {
  id: string;
  prompt: string;          // 题干/问题 (如: "404 Not Found")
  answer: string;          // 标准正解 (如: "服务器无法找到请求的资源")
  category: string;        // 细分类别 (如: "客户端错误")
  group?: string;          // 业务大类 (如: "HTTP状态码")
  layer?: 'L1' | 'L2' | 'L3'; // 认知层级
  distractorPool?: string[];// 专用诱惑项池
  explanation?: string;    // 解析与记忆法
  tags?: string[];
}
```

### 2. 同胞干扰项采样模型 (Sibling Distractor Synthesizer)
为了实现高质量的选择题与混淆题，摒弃随机无意义干扰项，提出**同胞优先 + 空间自适应退火模型**：
- **第一优先级（同胞池）**：同 `Group` + 同 `Category` + 同 `Layer` 的其余条目正解（混淆度最高，考验精细辨析）。
- **第二优先级（同组退火）**：若同分类条目不足 3 个，退火采样同 `Group` 内其余 Category 的条目。
- **第三优先级（全域兜底）**：若同组依然不足，采样整个题库其余分类条目，确保 100% 稳定生成 4 个互不重复的选项。

### 3. Markdown AST 双向解析与题库工坊 (Deck Studio)
- 制定大纲映射标准：
  - `# [题库标题]` ➔ 题库元数据与描述
  - `## [分组名称]` ➔ Group 分组
  - `### [类别名称]` ➔ Category 细分类别
  - `- 题干 :: 答案 [| 记忆法/解析]` ➔ 知识条目
- 开发 Deck Studio 工坊：
  - 支持直接粘贴 Markdown 文本，毫秒级实时解析为 KnowledgeDeck。
  - 支持表单可视化增删改查，并双向实时逆向生成标准 Markdown。

### 4. 知识容量与限制规范 (5-3-10 原则与 CRUD 防护)
- **黄金容量配置**：
  - 分类数建议：每个题库 $\le 5$ 个业务大类。
  - 层级深度：严格限制为 3 级（L1/L2/L3），杜绝深层树状结构导致的迷航。
  - 单分类条目容量：建议每个分类容纳 10～30 条，**最少不得少于 4 条**（保证四选一同胞池完整可用）。
- **增删改查限制提示**：
  - 当分类下条目 $< 4$ 条时，系统界面弹出黄色安全预警，告知干扰项将降级为同组退火采样。
  - 题库总容量超过 300 条时给出分卷建议，确保移动端与离线端丝滑流畅。
