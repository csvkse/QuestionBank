## 一、 优化背景与历史痛点 (单文件架构局限)

在 v2.0 初期，系统功能日趋强大，但代码形式依然是一个近 2500 行的超大型单文件 `index.html`：
1. **关注点高度混杂**：样式、核心算法（SM-2/干扰项采样）、界面渲染、状态机、题库数据全部挤在一个文件，多人协作或深度迭代极易引发回归。
2. **缺乏物理隔离约束**：UI 组件直接跨层修改全局数据，缺少明确的单一职责物理边界。
3. **缺失工程化门禁**：没有代码行数阈值限制、没有依赖单向流动校验、没有针对知识图谱完整性的自动化守门员。

│   ├── review/           # 艾宾浩斯复习流

### 1. 六大物理角色划分与单向依赖
严格对齐企业级前端架构 Core 2.1 物理角色标准：
- `app` ➔ 组装 `features`, `shared`, `design-system`；
- `features` ➔ 消费 `shared`, `design-system`；**严禁 Feature 之间产生双向紧耦合横向依赖**；
- `shared` ➔ 保持纯净无 UI 状态，不依赖上层业务；
- `platform` ➔ 封装音频合成、本地存储、键盘事件，屏蔽宿主差异。

### 2. 零依赖原生现代构建器 (`scripts/bundler.mjs`)
在维持“纯本地双击直接打开、离线零依赖交付”核心诉求的前提下，自研基于原生 Node.js 的打包器：
- **开发态 (Development Mode)**：所有源码保持原生 ESM 散列文件结构，单文件行数严格把控在 $\le 300$ 行以内。
- **分发态 (Production Distribution)**：运行 `node scripts/bundler.mjs`，在 ~12ms 内将 HTML 模板、CSS 样式表及 ESM 模块内联融合为高密度单文件 `index.html`。
- **双模并存**：开发者可本地启动 HTTP 静态服务调试散列源码，普通用户可直接双击根目录 `index.html` 使用完整系统。

### 3. L0 ~ L3 自动化质量门禁体系 (`gates/run-gates.mjs`)
构建 10 项严苛自动化门禁，全面杜绝架构退化：
- **L0 物理结构门禁 (`FE-STRUCT-*`)**：
  - `FE-STRUCT-DIR`：校验 6 大标准目录完整性。
  - `FE-STRUCT-SIZE`：单文件行数不得超过 350 行。
- **L1 知识图谱完整性门禁 (`FE-KNOW-*`)**：
  - `FE-KNOW-SCHEMA`：校验所有题库 JSON 的必填字段与数据合法性。
  - `FE-KNOW-CAPACITY`：预警条目数 $<4$ 的弱分类，防止同胞干扰项失效。
  - `FE-KNOW-AST`：校验 Markdown 解析器的双向 AST 转换幂等性。
- **L2 构建与交付门禁 (`FE-IMP-*`)**：
  - `FE-IMP-STANDALONE`：验证独立构建物 `index.html` 是否存在外部非托管 CDN 依赖。
