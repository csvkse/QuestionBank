SPEC-19 CORS Preflight Root Cause

CORS 预检阻断机理与本地开发反向代理解决方案

诊断分析针对 api.typesafe.ai 与公共代理 corsproxy.io 的报错根因，并提供 100% 稳定的工程化解法

返回应用

报错根因抓包实测证据 (Root Cause Diagnostic)

路径 1: 浏览器直连上游 HTTP 405 Blocked
> OPTIONS /v1/systemone HTTP/1.1
> Origin: null (file:// 页面)
> Access-Control-Request-Method: POST
< HTTP/1.1 405 Method Not Allowed
< Allow: POST
< (未返回任何 Access-Control-Allow-Origin)

分析：目标服务器仅支持 POST，应用层或 Cloudflare 规则对预检请求直接抛出 405，导致浏览器拦截。

路径 2: 公共代理 corsproxy.io HTTP 401 Unauthorized
> OPTIONS /?url=https%3A%2F%2Fapi... HTTP/1.1
> Origin: null
> Access-Control-Request-Headers: authorization
< HTTP/1.1 401 Unauthorized
< {"error":"A valid API key is required"}

分析：公共代理现已要求注册付费 API Key。预检收到 401（非 200~299 OK 状态），浏览器抛出 does not have HTTP ok status。

三种解决途径全维度技术对比

方案类别 实施方式 稳定性 & 速度 隐私与安全性 推荐度
方案 1: 内置 Node.js 本地开发服务与代理 (推荐) 终端运行 npm run dev
浏览器访问 http://localhost:3000		 100% 极速直连，0 速率限制 本地进程转发，Token 不经第三方 首选 (开箱即用)
方案 2: 自建 Cloudflare Worker 云代理 CF 后台部署 15 行 JS 脚本
https://worker.dev/?url=		 全球边缘 CDN，稳定性极高 专属 CF 账户隔离，安全可控 纯静态部署优选
方案 3: 第三方免费公共代理 (如 corsproxy.io) 前缀挂载公共 URL 随时收费或下线，已报 401 严重隐患：API Key 泄露给第三方 废弃 (不可用)

方案 1 落地：零依赖内置本地开发代理 (scripts/dev-server.mjs)

1. 一键启动服务

在项目根目录运行命令：

npm run dev

自动托管项目静态资源，并开启 /api/proxy 反向代理通道。

2. 访问应用

浏览器中直接访问：

http://localhost:3000

告别 file:// 的 origin: 'null' 限制，享受标称标准同源上下文。

3. 接口自动透传

JEV 或模型端点代理前缀：

http://localhost:3000/api/proxy?url=

自动拦截预检返回 204，上游 POST 直接转发，100% 成功。
